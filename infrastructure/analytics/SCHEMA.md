# Typed event schema v1

The selection is **142 source properties plus eight derived browser intervals**. The number is an outcome of reviewing useful event families, not a quota. The complete source-to-column contract is in [event_schema.json](event_schema.json); [003_typed_events_v1.sql](sql/003_typed_events_v1.sql) is generated by `typed_schema.py`.

## Selection judgment

| Area | What is promoted | Why |
| --- | --- | --- |
| Identity and content | Separate user, client, tab and session IDs; content IDs; displayed user; previous session | Supports joins, cohorts and journeys without conflating actors, content or identity namespaces. |
| Navigation and attribution | `to`, `from`, post transitions, path/URL/referrer/href, UTM values, page/section/element/modal context | Makes `navigate`, `pageLoadFinished` and link events useful directly. URLs remain strings, preserving query strings and fragments. |
| Browser and rendering | Device/browser flags, user agent, memory, complete standard navigation timing endpoints, server render timings/cache/server | Completes coherent performance analyses. Rare CPU, wall-time and SQL-volume measurements can explain expensive renders. |
| Engagement | Timer increment and cumulative seconds separately; visibility, intersection, activity, hover and observer data | Preserves units and distinguishes time spent from observer timestamps or cumulative counters. |
| Feed and recommendations | Feed/content/occurrence IDs, indices, algorithms, scores, sources, session context, mounted posts, recommendation scenarios | Supports exposure-to-interaction analysis. Arrays remain ordered and events are not multiplied by flattening a list. |
| Experiments | Assignment and recorded-as-used maps | Dynamic experiment names belong in maps. Assignment alone does not establish actual exposure. |
| Search, audio and UI | Search text/result/type/rank; playback position/speed/episode/chapter; explicit interaction outcomes, dialog/form/error context | Low-frequency outcomes remain useful. Absence is not interpreted as a negative outcome. |

The additions beyond the initial 100 suggestions and four identity columns complete browser timing, feed feedback references, search context, audio navigation and UI outcomes. Rarity alone is not a reason to omit a field.

We leave these in the original JSON for now:

- Arbitrary component props, GraphQL/filter/terms objects and content snapshots: their structure and meaning vary. A flattened name would imply a consistency the source does not have.
- Dynamic post IDs and experiment names as individual physical columns: their values already fit typed maps or arrays.
- IP addresses, full content and other large/free-form context: retain the original, but no concrete workload currently justifies duplicating them as separate columns. Raw data and promoted columns have the same private access boundary.
- Old or ambiguous metrics such as numeric `timeToCapture`, `timeToNonBlankPaint`, or an unrelated event's `state`/`position`: retain them without guessing their units or equating different meanings.
- Tab/session enrichment: this schema extracts what each event actually recorded. Carrying browser or experiment data across events requires a separate decision about event-time validity and ambiguous joins.

## Interpretation contract

`event_json` remains the exact original JSON text in both the immutable archive and the destination. A later extraction can run from those copies without re-exporting RDS. Unknown fields, malformed values and unselected structures are retained there. This does not make a future full-history materialization free; it makes it possible without losing the source.

Scalar columns are nullable. Arrays and maps use ClickHouse's empty default and accompanying presence metadata:

| State | Value column | Metadata |
| --- | --- | --- |
| Missing | NULL, or empty collection | Not in `property_present` |
| Explicit JSON null | NULL, or empty collection | In `property_present` and `property_null` |
| Valid false, zero, empty string or empty collection | Original value | In `property_present`, without an invalid/null flag |
| Wrong type, overflow, malformed collection member | NULL, or empty collection | In `property_invalid`; entire original remains in `event_json` |
| Property belongs to a different event family | NULL, or empty collection | In `property_out_of_scope` |

Numbers are not parsed from strings. Booleans are not integers. Int64 overflow and non-finite Float64 values are flagged. Floating-point measurements use Float64 and can round high-precision decimals; the exact original numeric text remains available. The pinned ClickHouse 26.3 JSON parser can add a few binary rounding steps, and its `precise_float_parsing` setting does not fix that input path. Readback permits at most four Float64 ULPs and reports the observed error; IDs, integer counts, timestamps and raw JSON compare exactly. A general absolute tolerance would hide errors in tiny measurements, so it is not used. [Upstream issue and version boundary](https://github.com/ClickHouse/ClickHouse/issues/60146).

Array order and duplicate members survive. A malformed member flags the whole typed collection rather than silently dropping that member.

`property_sources` records aliases or wrapper paths; `property_normalized` identifies destination-object, threshold-scalar and timestamp normalization. `property_conflicts` records differing candidates. Precedence is top-level, then legacy `props`, then legacy `props.eventProps`; the canonical path wins over its aliases within each layer. An explicit preferred null is not replaced by an alias value.

Legacy unwrapping only applies when `payload.type` matches the envelope event type and `props.eventProps` is an object. An ordinary object named `props` is not automatically flattened. `browserProps.userAgent` is an explicit fallback for `userAgent`. The historical search alias `q` is scoped to search events.

Specific meanings that are easy to misread:

- `navigation_to` accepts a string or a location object containing only `pathname`, `search`, and `hash`. It is populated for `navigate`, `linkClicked`, and `linkMounted`; `navigation_from` is scoped to `navigate`. A destination is not inferred from another event or joined to a post ID.
- Sum `increment` for timer seconds. `seconds` is cumulative. `in_view_time_ms` is the observer's clock value, not elapsed engagement time.
- `hover_captured_at` parses timezone-bearing ISO strings. Current code records a `Date`; historical numeric `timeToCapture` values remain raw and flagged because their units are unproven.
- Browser timing endpoints are epoch milliseconds. `page_ttfb_ms` specifically means `responseStart - requestStart`; it excludes earlier navigation/DNS/connect phases. Other derived intervals are listed in `typed_schema.DURATIONS`. Missing, zero or reversed endpoints yield NULL; valid equal nonzero endpoints yield zero. The load handler can record `loadEventEnd = 0` before its own completion.
- `performance.memory` is the producer's `usedJSHeapSize`, mapped to `browser_used_js_heap_bytes`. Historical `timings.cpuTime` and `timings.wallTime` retain their recorded units and are not silently added to millisecond intervals.
- `post_ids_with_scenario[].generated_at` is an optional original string: curated/stickied records legitimately omit it. Arrays of mount/scenario records do not create extra event rows.
- `post_visibility` preserves the producer's map verbatim. Current `usePostsList` passes `hiddenPosts` under that name, so `true` must not be relabeled as a visible impression. Use actual visibility/intersection events for that question.
- General sessions, UltraFeed sessions and recent-discussion sessions remain separate. `feedback_event_id` and `served_event_id` are references, not the canonical archive `event_id`.

## Versioning and opt-in operation

The destination is separate: `analytics.raw_events_typed_v1`, canonical `analytics.events_typed_v1`, and `analytics.applied_batches_typed_v1`. The old pilot table/view are unchanged. The new view explicitly includes materialized columns and uses `FINAL` to avoid replay-inflated counts. Query users can read canonical views but cannot read raw tables or receipts.

`extractor_fingerprint` covers the registry, parser and generated-schema code. `properties_hash` covers the projected values and their metadata before database parsing; it is a reconciliation marker, not an independently recomputed database digest. Field readback separately checks storage conversion. A receipt with a different fingerprint fails closed. Once a version is in use outside a disposable fixture, change the version and create a new destination for a revised contract; never edit extraction rules behind existing receipts. Reconcile the new version before switching queries.

With the service stopped and normal operator credentials/state configured:

```sh
python cli.py --event-schema typed-v1 init
python cli.py --event-schema typed-v1 replay
# Only after the separately approved source capture/rollout:
python cli.py --event-schema typed-v1 cycle
```

`ANALYTICS_EVENT_SCHEMA=typed-v1` selects the same destination for the worker and its readiness check. Default operation remains `legacy`. Backup covers the entire analytics database; restore clears receipts for every restored schema version, so replay each retained version before treating its view as reconciled.

Replay groups at most 50,000 rows or 64 MiB of uncompressed archive envelopes, whichever comes first, with one pooled HTTP session. A group uses five requests: receipt lookup, pre-insert identity check, insertion, post-insert reconciliation and receipt insertion. Already received groups use one request. External ID tables remove the old 500-ID URL chunking. Expanded projections and Python objects use more memory than the archive byte limit; see measured peak memory in the evaluation evidence.

The original JSON and the two per-row content/projection hashes use ZSTD(3). Compressing the hexadecimal hashes avoids spending nearly as much space on each validation hash as on the complete original payload in the sample. This changes storage encoding, not query values or source retention.

## Reproducible checks

```sh
# Read-only, schema-only counts. The private output includes event names, which
# can themselves contain malformed/scanner input; do not publish it wholesale.
python audit_extraction.py --archive PRIVATE_ARCHIVE --output PRIVATE_AUDIT.json

# Requires the explicitly disposable local fixture and ANALYTICS_TEST_MODE=1.
# Resets its analytics database. Never point it at shared infrastructure.
python measure_typed.py --archive PRIVATE_PILOT --archive PRIVATE_HISTORY \
  --verify-archive PRIVATE_HISTORY --output PRIVATE_METRICS.json
```

Readback compares all promoted columns, metadata, derived intervals and original JSON for every event in the requested validation archives. It verifies storage conversion against the extractor, not the truth of the producer's semantics. Independent raw-JSON comparisons additionally check timer increments, navigation destinations and browser response timestamps across the loaded dataset.

The historical inventory covers all 4,565 sampled event names across 30 quarters but takes at most the first 25 rows per type/quarter. The pilot consists of four bounded date windows. These are useful shape audits, not exhaustive field coverage or unbiased event-frequency estimates. Full-history throughput, disk capacity, query layout and source export remain separate gates.
